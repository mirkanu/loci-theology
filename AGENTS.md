# AGENTS.md — loci-theology

Repo-specific guidance for any agent (human or AI) editing this repository.

## Source of truth

`data/loci.ttl` is the canonical source. Everything else (the static site
in `dist/`, the JSON-LD export, the validation report) is derived. Never
edit `dist/` by hand — it is regenerated by `tools/build_site.py` in CI.

## Format

- **Turtle (`.ttl`)** — canonical, git-diffable, easy to review.
- **JSON-LD** — emitted as a build artefact in `dist/loci.jsonld`. Useful
  for consumers who want to drop the taxonomy into a JS/TS app.

## Modelling rules

1. **Hierarchy** uses `skos:broader` / `skos:narrower`. There are no
   orphan concepts: every non-Locus `loci:Doctrine` or `loci:Topic` must
   have at least one `skos:broader` parent. This is enforced by SHACL.
2. **Cross-relations** are typed object properties declared in
   `ontology/loci-ontology.ttl`. Allowed values:
   - `loci:dependsOn` — premise–conclusion
   - `loci:groundsIn` — supported by
   - `loci:presupposes` — assumes without arguing for
   - `loci:contrastsWith` — symmetric
   - `loci:fulfilledBy` — eschatological / typological
   - `loci:appliesTo` — ranges over
   - `loci:distinctFrom` — symmetric, semantic gap
   - `skos:related` — generic symmetric association
   Adding a new typed relation requires editing the ontology file and
   explaining it in a PR.
3. **Labels**: every concept must have exactly one `skos:prefLabel` per
   language. `skos:altLabel` is for cross-tradition aliases and must be
   tagged with a language.

## Local development

```bash
pip install rdflib pyshacl
python tools/validate.py            # SHACL validation
python tools/build_site.py          # build static site into dist/
```

## CI / deploy

- `validate` job runs on every push and PR.
- `build-site` job publishes `dist/` to GitHub Pages on `main`.
- `preview` job publishes a Pages preview for PRs.

## Repo etiquette

- Do not add explanatory content (definitions, scripture references,
  exegesis). Labels and relations only.
- Open an issue before proposing a new typed relation or a restructure
  of a Locus's tree.
- One locus per PR is a good default.
